# 1. PURPOSE

This document defines how Vepari AI stores, protects, synchronizes, remembers, observes and serves data across the complete platform.

The architecture is:

```text
                    VEPARI AI
                        │
          ┌─────────────┼─────────────┐
          ↓             ↓             ↓
       DEVICE         CLOUD           AI
          │             │             │
       SQLite       Database        Memory
          │             │             │
       Files        Object Store   Context
          │             │             │
          └─────────────┼─────────────┘
                        ↓
                     SYNC
                        ↓
                 SHARED BUSINESS
                     STATE
                        │
             ┌──────────┼──────────┐
             ↓          ↓          ↓
           AUDIT       LOGS      EVENTS
```

# 2. CORE DATA PRINCIPLE

Vepari AI has **two different kinds of persistence**:

### Local

Designed for:

- offline operation
- fast UI
- device continuity
- local business access
- AI context where appropriate

### Cloud

Designed for:

- shared business state
- multi-device synchronization
- team collaboration
- authoritative records
- backups
- integrations
- cross-device AI context

---

# 3. SOURCE OF TRUTH MODEL

The most important distinction is:

```text
Local SQLite
    ↓
Local operational state

Cloud database
    ↓
Authoritative shared business state
```

The local database is not an independent competing business system.
