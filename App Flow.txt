# VEPARI AI
# MASTER APP FLOW DOCUMENT

**Document Status:** Master / Consolidated  
**Product:** Vepari AI  
**Platform:** Android-first mobile application  
**Future Platform:** iOS  
**Technology Direction:** React Native + Expo + TypeScript  
**Business Scope:** Micro → Small → Medium → Enterprise  
**Language Scope:** 23 Indian languages  
**Core Experience:** AI-native, local-first, offline-first  
**Design Identity:** Official Vepari AI design system, with Lora as the primary English display/brand font  
**Primary Navigation Model:** Mobile-first, AI-centered business workspace

---

# 1. PURPOSE

This document defines the **complete end-to-end application flow of Vepari AI**, from the moment the user launches the application to daily business operations, AI interaction, offline operation, synchronization, integrations, settings, security, and eventual iOS expansion.

It combines the decisions already established across:

- Product requirements
- UI/UX
- Frontend architecture
- Backend/API architecture
- Database architecture
- Local mobile storage
- AI OS
- AI memory
- Voice
- Multilingual system
- Security
- Cloud
- Offline/sync
- Connection Portfolio
- Implementation roadmap

The objective is that a designer, developer, tester, product manager, or Claude Code can understand **how the entire application behaves as one system**.

# FINAL CONCLUSION

The **Vepari AI Master App Flow is now consolidated**.

It covers the complete user journey and the underlying system journey:

**Launch → Security → AI OS → Business Briefing → Home → Business Operations → AI → Memory → Actions → Finance → Documents → Reports → Team → Automation → Offline → Sync → Connections → Settings → Recovery → Repeat.**

The most important product behavior remains:

> **The owner secures the app first. Vepari AI then awakens, understands what happened while the owner was away, presents the important business resources and events, and lets the owner move directly from understanding to action.**

And technically:

> **Core business operation remains local-first and offline-first, with encrypted SQLite as the local business data foundation, custom accounting as the financial engine, on-device memory for AI context, and optional controlled cloud/synchronization capabilities.**

This App Flow document therefore sits alongside the **Master PRD** and **Master TRD** as the consolidated behavioral specification for implementation.
