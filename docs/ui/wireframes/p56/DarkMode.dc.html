Phase 5 · Product Decision · P56
Dark Mode — In Scope or Deferred?
Depends on: P46 Color Tokens · Trigger: "Theme: Light" row on Settings screen in Screens.png
Decision
Dark mode is IN SCOPE for the design system — warm tokens defined now; implementation deferred to Phase 7.
Tokens are defined in this phase so Phase 6 engineers never have to retrofit semantics onto a palette that was designed for one mode only. The warm dark palette preserves the gold-and-cream character rather than defaulting to generic dark-slate.

UI implementation (React Native dark appearance) is deferred to Phase 7: the "Theme: Light" row in Settings confirms the light mode ships first and a toggle is planned, but building the toggle before the core screens are complete would split Phase 6 capacity.
Trigger Evidence
Settings screen — Screens.png

The Settings screen contains a row labelled "Theme: Light". A value with a current selection implies an alternative exists — if light-only, the row would simply not exist. This is an unambiguous signal that dark mode is planned.

Master documents

None of the 9 master documents specify dark mode explicitly, nor do any of them rule it out. The ambiguity is structural — the Settings screen shows intent that the document corpus never articulated. P56's job is to resolve this.

User base context

Indian MSMEs using the app in low-light conditions (evening accounting, night markets) and on OLED screens benefit substantially from a warm dark theme. Battery savings on OLED displays are a practical concern for this audience.

Risk of deferring tokens

If dark mode tokens are not defined before Phase 6, every hardcoded color in component code becomes a debt to refactor. Defining semantic tokens now (surface, on-surface, accent) costs one design session; retrofitting costs a sprint.

Deferred — Phase 7
1
React Native Appearance API integration — wiring useColorScheme() and the StyleSheet conditional to the token set; testing on Android and iOS for system-level dark mode follow.
2
In-app theme toggle — the Settings screen "Theme" row; user preference persistence (AsyncStorage or SecureStore); default to system preference on first launch.
3
Screen-by-screen dark QA — verifying that every screen that ships in Phase 6 renders correctly in dark mode; catching edge cases (image overlays, transparent sheets, camera preview surfaces).
4
Sarvam AI surface in dark mode — the AI Indigo (#4A3D6B) surface used for voice transcription and AI responses requires its own dark adaptation; deferred until the AI OS screens are built.

Design observations
Warmth preserved. Dark backgrounds use brown-black (#1E1810), not slate — the MSME audience sees continuity with the brand, not a generic dark app.
Gold accent stays gold. dm-Gold (#D4A853) is slightly warmer/more saturated than #C8A96B to compensate for the luminance shift. It remains decorative on most dark surfaces.
Status colors lightened. dm-Olive and dm-Terracotta are lightened on the dark ground to maintain WCAG AA — the semantic meaning (up = good, down/unfavorable = warning) is intact.
Bottom nav separates cleanly. The dm-Border line at #4A3C30 gives just enough lift between nav and content without a harsh contrast jump.
Gold Text in Dark Mode — Usage Rules
⚠️
Heritage Gold is STILL not free text on most surfaces in dark mode. dm-Gold (#D4A853) on dm-Surface (#2C231B) = 3.6:1 — passes for large text and UI components (≥3.0:1) but not for body text (≥4.5:1). The same rule from P55 applies: Gold text is permitted only on Deep Brown surfaces, or as a decorative element with a non-gold supporting label.

Trigger
"Theme: Light" row in Screens.png Settings screen implies a planned dark mode that no master document addresses. Left unresolved, it becomes a Phase 6 retrofit risk.
Decision
Dark mode is in scope. Warm dark-palette tokens are defined in Phase 5 alongside the light palette. React Native implementation and in-app toggle are deferred to Phase 7 after the core screens ship.
Rationale
Token definition now costs one design session. Retrofit after Phase 6 costs a sprint plus regression risk on every screen. The "Theme: Light" row leaves no room for ambiguity — dark mode was always planned.
Tokens
12 new dm- tokens added to P46. Semantic alias table updated with light/dark pairing for all 14 semantic slots. See this canvas for the full table.
Constraints
Gold accent remains decorative on most dark surfaces (3.6–4.0:1). Gold as body text requires dm-Background (#1E1810) as the surface (7.8:1). Identical rule to the light-mode constraint from P55.
Next steps
Phase 6 engineers reference semantic tokens only — no raw hex in components. Phase 7 ticket: "Wire dark mode toggle in Settings + useColorScheme()". Sarvam AI surface dark adaptation is a Phase 7 sub-task.
