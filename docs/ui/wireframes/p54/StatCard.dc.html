Core accessibility rule: Status is never conveyed by color alone. Every up/down indicator pairs three independent cues — (1) a directional icon, (2) a percentage/absolute change label, and (3) a text label. The card passes a grayscale test: meaning is fully clear with all color removed.

4 · Trend Color and Icon Logic
The trend indicator encodes two independently varying things: (1) direction (value went up or down) and (2) valence (is this good or bad?). For Revenue and Profit, up=good. For Expenses, down=good. The component uses the same icon direction as the actual movement — it does NOT flip the arrow to represent "good/bad". Color encodes valence (green=favorable, red=unfavorable) and the label text adds a semantic layer.

Expenses valence logic: Expenses going up is unfavorable (red). Expenses going down is favorable (green). The component receives a direction ("up"/"down"/"neutral") and a valence ("favorable"/"unfavorable"/"neutral") as separate props — never infer valence from direction alone, since it differs by metric type. The caller (e.g. Finance screen) supplies both based on business context.

6 · Implementation Rules
✓ Do
  • Always include the directional icon — never percentage label alone
  • Always include the percentage/amount change — never icon alone
  • Use explicit +/− prefix on percentage (never rely on color for sign)
  • Receive direction and valence as separate props
  • Show "vs last month" period label — user must know the comparison period
  • Format value in lakh/crore abbreviations per P52: ₹8.4L, ₹1.2Cr
  • Use U+2212 (−) for minus, not ASCII hyphen-minus (−)
  • Test each new card variant in grayscale before shipping
✗ Don't
  • Don't use color as the only indicator of trend direction
  • Don't infer valence from direction — Expenses down is favorable
  • Don't truncate the metric value — resize font before truncating (min 16sp)
  • Don't use green/red without the icon and label (fails grayscale)
  • Don't show a plain percentage without the +/− sign
  • Don't display Devanagari digits for the value — always Latin 0–9
  • Don't use a filled arrow icon — outline/stroke arrows only (less aggressive)
  • Don't omit the period label — "12.4%" alone is ambiguous
7 · Component Props Interface (Reference)
interface StatCardProps {
  label: string;           // "Revenue" | "Expenses" | "Net Profit"
  value: string;           // Pre-formatted: "₹8.4L", "₹1.2Cr"
  direction: 'up' | 'down' | 'neutral';  // Actual movement
  valence: 'favorable' | 'unfavorable' | 'neutral'; // Context meaning
  changePercent: number;   // e.g. 12.4 (negative = decrease)
  period: string;          // "vs last month" | "vs last year" | "vs last week"
  onPress?: () => void;    // Navigate to Finance drill-down
}
