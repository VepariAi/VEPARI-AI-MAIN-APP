P51 — Motion Physics and Haptics

Prompt 51 · Phase 5 · Depends on Prompt 16 — AI OS physics language, haptics map, reduced-motion fallbacks per AI OS.txt §18, UI-UX §21, §124, §125, §196
Core principle: Motion in Vepari AI is purposeful, not decorative. Every animation conveys state change, spatial relationship, or AI activity. The AI OS physics language uses spring curves — not linear or cubic-bezier tweens — because springs feel alive and match the "breath" metaphor of the AI Core. Reduced-motion equivalents MUST preserve semantic meaning (state changed, something succeeded, AI is active) through opacity transitions or instant-cut, never by simply removing feedback entirely.

Spring Presets — AI OS Physics Language

React Native Reanimated spring parameters: withSpring(value, {stiffness, damping, mass}). For CSS contexts (web preview): spring(stiffness: S, damping: D) in @keyframes or transition: property Xs cubic-bezier(approx). Reduced-motion always replaces spring with withTiming(duration, {easing: Easing.out(Easing.quad)}) or CSS transition: property 0ms (instant) / 150ms ease-out (minimal fade).

Haptics Map (UI-UX §124)

Haptics are triggered via react-native-haptic-feedback (or Expo Haptics on managed workflow). All haptics are optional — they are skipped when the device has haptics disabled in system settings. Never use haptics for passive state (scrolling, animation). Only on explicit user action or important AI state change.

Reduced-Motion System (UI-UX §125, §196)

React Native: check AccessibilityInfo.isReduceMotionEnabled() on mount and subscribe to changes. Store as app-level context. Web: @media (prefers-reduced-motion: reduce). The setting applies to ALL animations app-wide — no per-screen override.

Haptics and reduced-motion are independent settings. isReduceMotionEnabled disables animations only — it does NOT disable haptics. Haptics remain active in reduced-motion mode unless the system's "reduce haptics" setting is separately enabled. Never gate a haptic call on the reduced-motion flag.
