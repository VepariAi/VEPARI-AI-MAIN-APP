# VEPARI AI — PROJECT MASTER INSTRUCTIONS

## 1. PROJECT IDENTITY

Project name: Vepari AI

Vepari AI is the single product, identity, platform and source of truth for this project.

Do not use, introduce, revive or substitute any other product name or concept unless explicitly instructed by the team.

Vepari AI is an AI-powered, mobile-first business intelligence and operating platform for MSMEs across India.

It serves the complete MSME ecosystem, from very small/micro businesses to more structured small and medium enterprises.

Micro enterprises are an especially important segment, but Vepari AI is NOT limited to micro enterprises.

The micro-business segment should have a significantly deeper and more specialized feature ecosystem because these businesses often have different workflows, technology adoption levels, language needs, operational constraints and business problems.

---

# 2. PRODUCT VISION

Vepari AI is intended to become the:

"AI Business Brain for MSMEs"

Core philosophy:

VOICE → MEMORY → INTELLIGENCE → ACTION

The product should help businesses:

- capture business activity
- remember important business information
- understand financial and operational reality
- identify problems
- discover opportunities
- receive recommendations
- make better decisions
- take useful actions
- build long-term business continuity

Vepari AI should not be treated as merely:

- a billing app
- an accounting app
- a ledger app
- a chatbot
- a voice assistant
- a CRM
- an ERP
- a government-scheme portal

It should unify these capabilities into an intelligent business platform.

# 7. MULTILINGUAL INDIA-FIRST ARCHITECTURE

Vepari AI is NOT Tamil-only.

Tamil is an important flagship language and an important initial design/reference language, but the product must be designed as a multilingual Indian platform.

The architecture must support Indian languages without requiring a redesign of the application.

The current Sarvam AI speech stack provides coverage for 22 Indian languages plus English for relevant models such as Saaras v3/v4.

Relevant language set includes:

- Assamese
- Bengali
- Bodo
- Dogri
- Gujarati

- language selection

---

# 8. LANGUAGE INDEPENDENCE

Business data must never be structurally dependent on one language.

For example:

A customer record should not become a different customer merely because the user changes from Tamil to Hindi.

Business entities, IDs, transactions and relationships must remain language-independent.

The UI language is separate from the underlying business data model.

The AI should understand multilingual and code-mixed business conversations where supported.

---

# 9. PRIMARY PRODUCT EXPERIENCE

The central interaction should be:

OPEN
→ SPEAK
→ UNDERSTAND
→ CONFIRM
→ REMEMBER
→ ANALYZE
→ ACT

Example:

A user speaks a business event.

The system should:

1. capture voice
2. transcribe it
3. identify language
4. interpret intent
5. extract business entities
6. identify financial/business values
7. determine required action
8. show the user what was understood
9. ask for confirmation when appropriate
10. save structured business information
11. update relevant business intelligence
12. provide useful feedback

The AI must not silently perform important financial actions without appropriate confirmation rules.

# 13. DEVICE AND TEAM DEVELOPMENT ENVIRONMENT

There are six team members.

The same development project may be accessed from:

- the primary developer's laptop
- other team members' laptops
- friends' laptops
- Android development devices
- potentially other computers used temporarily for development

The project must therefore NEVER depend on one physical computer.

The source code must live in a shared remote Git repository.

The repository is the development source of truth.

Claude Code sessions are NOT the source of truth.

A Claude Code session may start and end on any device.

A developer must be able to:

1. clone the repository
2. install dependencies
3. configure permitted environment variables
4. pull the latest branch
5. work with Claude Code
6. run tests/builds
7. commit changes
8. push changes
9. continue from another machine later
