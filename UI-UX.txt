# VEPARI AI
# MASTER UI/UX REQUIREMENTS DOCUMENT

**Document:** Master UI/UX Specification  
**Product:** Vepari AI  
**Status:** Consolidated Source of Truth  
**Platform:** Android-first mobile application  
**Future:** iOS  
**Framework:** React Native + Expo + TypeScript  
**Business Scope:** Micro → Small → Medium → Enterprise  
**Languages:** 23 Indian languages  
**Design Philosophy:** AI-native · Mobile-first · Local-first · Offline-first · Privacy-first  
**Primary Typography:** Lora for English display/brand typography  
**Visual Identity:** Official Vepari AI palette and typography system  
**AI Experience:** Cinematic spatial AI OS, inspired by the interaction quality of futuristic personal AI interfaces, but uniquely branded as Vepari AI

---

# 1. UI/UX VISION

Vepari AI should not feel like a collection of traditional business-management screens.

It should feel like:

> **A living business operating system that the owner can see, speak to, and operate.**

The interface combines:

```text
Business Software
        +
AI Assistant
        +
Business Intelligence
        +
Mobile Operating Experience
```

The application should progressively move the user from:

**Seeing → Understanding → Deciding → Acting.**

# 3. DESIGN CHARACTER

The Vepari AI interface should communicate:

- intelligent
- premium
- trustworthy
- futuristic
- calm
- powerful
- professional
- Indian
- multilingual
- approachable

It must **not** look like a generic accounting app.

It must also **not** become so futuristic that everyday business operations become difficult.

---

# 4. VISUAL IDENTITY

The official Vepari AI design system is the single visual source of truth.

Use:

- official Vepari AI color palette
- approved typography
- Lora for primary English display/brand typography
- approved multilingual font fallbacks
- official logo
- official iconography
- established spacing
- established component shapes
- established AI OS visual language

No new palette should be introduced during implementation.

---

# 5. COLOR SYSTEM

The implementation must use the **previously approved official Vepari AI palette** consistently.

The palette should be represented as design tokens rather than hardcoded colors.

Example architecture:

```text
colors/
├── primary
├── secondary
├── accent
├── background
├── surface
├── elevated
├── text
├── border
├── success
├── warning
├── error
├── info
└── ai
```

The exact official color values already established for Vepari AI must be used by the implementation.

---

# 6. COLOR SEMANTICS

Colors have meaning.

```text
Primary
→ brand / primary interaction

Accent
→ important interactive emphasis

Success
→ completed / healthy

Warning
→ attention

Error
→ failure / danger

Info
→ information

AI
→ AI-generated / AI interaction
```

Color must never be the only way to communicate status.

# 120. FORMS

Forms should:

- use clear labels
- show validation inline
- preserve user input
- support keyboard navigation
- support multilingual expansion
- provide appropriate defaults

---

# 121. FORM VALIDATION

Validation should be:

```text
Immediate where helpful
+
Complete on submit
```

Errors should be attached to the relevant field.

---

# 122. KEYBOARD UX

Forms must work naturally with mobile keyboards.

The interface should:

- scroll focused fields into view
- avoid keyboard covering actions
- provide correct keyboard types
- support numeric fields properly

---

# 123. TOUCH TARGETS

Interactive controls must have sufficiently large touch areas.

Do not optimize for visual compactness at the expense of usability.

---

# 124. HAPTICS

Haptics can reinforce:

- successful actions
- confirmations
- important AI states
- errors
- selected controls
